# Serving an app's skills to an external harness

## Modern endpoint verification

On the updated local Relay, the official SDK 2.4.0 client in `versionNegotiation: { mode: "auto" }` selects MCP 2026-07-28. The same endpoint serves tools and verified skill files. Apify mcpc 0.8.0 selected 2026-07-28, listed the skill, read the Markdown body and then read its separate reference. The observed requests included `server/discover`, `subscriptions/listen`, `skills/list`, `skills/get` and `resources/read`. A bare legacy initialize request received HTTP 400 with JSON-RPC error `-32022`. These probes used a local HTTP server and a ticketed WebSocket. ## What an app can ship

An app can publish one directory per skill, with a `SKILL.md` containing a frontmatter `name`, a `description` that identifies when to use it, and the instructions. A single Markdown file is sufficient. Relative files such as `references/layout.md` belong to the same directory. The harness can show the metadata, load the body when its model selects the skill or a person invokes it, and read individual references when needed. A description should tell the model how to recognize the task. Registering a skill cannot guarantee that a model will select it. [Agent Skills specification](https://agentskills.io/specification) · [Client integration guide](https://agentskills.io/client-implementation/adding-skills-support)

Use `createMcpApp` with the app's own files. A statically bundled Markdown string works for a browser app. An app can expose skills with zero app tools or alongside separately supplied tools. A workflow that uses tools should describe the actual operations its app offers. The harness continues to own discovery, model context and activation. The app that owns a tool continues to authorize and execute its effects. [MCP Skills overview](https://modelcontextprotocol.io/extensions/skills/overview) · [Exterior's Code Mode contract](../adr/0032-an-app-serves-code-mode-with-pi.md)

## The existing TypeScript implementation

The public `@modelcontextprotocol/server/ext/skills` entry in **2.4.0** supports in-memory files, storage-backed files and a generated per-request catalog. The Node-only subpath adds filesystem discovery. The SDK handles manifest generation, frontmatter, digests, pagination and resource handlers. The original investigation considered adopting this package for Skills while Code Mode still used its v1 MCP peer. On a legacy initialized MCP session, both ends can speak the extension. [Published server exports](https://registry.npmjs.org/@modelcontextprotocol/server/2.4.0) · [Server guide and examples](https://github.com/modelcontextprotocol/typescript-sdk/blob/46d9c9921b6542e813c1ecc5f9fc964085e8e3bb/docs/servers/skills.md) · [Manifest at the time of the probe](https://github.com/lulu0119/exterior/blob/f5ab618/packages/client-sdk/package.json)

This is executable upstream SDK usage. The app can reuse the catalog across its own endpoint's requests and attach it to a fresh server for each one, as Exterior's `serveMcp` expects. [Server implementation](https://github.com/modelcontextprotocol/typescript-sdk/blob/46d9c9921b6542e813c1ecc5f9fc964085e8e3bb/packages/server/src/ext/skills/extension.ts) · [Exterior page transport](../../packages/sdk/src/client/mcp.ts)

```ts
import { McpServer } from "@modelcontextprotocol/server"
import { memorySkillFiles, SkillsExtension } from "@modelcontextprotocol/server/ext/skills"

const catalog = await SkillsExtension.load(memorySkillFiles({
  "app-layout/SKILL.md": layoutSkillMarkdown,
  "app-layout/references/layout.md": layoutReference,
}), { strict: true })

await serveMcp(relayUrl, accessToken, async transport => {
  const server = new McpServer({ name: "example-app", version: "1.0.0" })
  catalog.attach(server)
  await server.connect(transport)
})
```

SEP-2640 is Final. A server advertises Resources and `io.modelcontextprotocol/skills`. `skills/list` returns frontmatter and a manifest, and `skills/get` looks up an entry by URI, including unlisted skills. **The Markdown body travels in `resources/read`.** The official `SkillsClient` verifies bytes and frontmatter and resolves relative resources. Origin is the server identity plus the skill URI. The host owns selection, attribution, approvals and any approved script execution. Both a second server using the same URI and a changed manifest matter at this level. [Extension specification](https://modelcontextprotocol.io/seps/2640-skills-extension) · [Client SDK guide](https://github.com/modelcontextprotocol/typescript-sdk/blob/46d9c9921b6542e813c1ecc5f9fc964085e8e3bb/docs/clients/skills.md)

**Local transport probe.** With the published 2.4.0 client and server, a loopback HTTP service used Exterior's real `createMcpEndpoints`, a WebSocket and `serveMcp`. The fixture supplied the endpoint-opening route and identity. Both the default client configuration and explicit legacy negotiation produced `initialize → notifications/initialized → skills/list → resources/read → resources/read`. The list contained one skill and two file entries, with neither the body nor the reference text. Both subsequent reads returned the expected content and passed digest verification. A strict TypeScript check also accepted Exterior's transport directly as the argument to v2 `McpServer.connect`. This checks the route for a consuming MCP client. No model or deployed OAuth flow participated. **Third-party CLI probe.** Apify mcpc 0.8.0 connected to the same local Exterior relay with its default configuration and reported the Skills capability. It negotiated MCP 2025-11-25. Its `skills-list`, `skills-get`, and attachment read exited with status 2 at the CLI's version check, before sending a skill request. Its Skills commands require MCP 2026-07-28. ## What ACP adds

ACP v1 lets a client supply an HTTP MCP endpoint through `mcpServers` when the agent advertises that transport. A remote skill can therefore reach a host that implements SEP-2640 using the same Exterior endpoint as any other MCP server. A page reload creates a new endpoint, whose address and authorization must be supplied on the next applicable session setup. A working HTTP MCP connection proves transport, and skill discovery requires a consuming host. [ACP session setup](https://agentclientprotocol.com/protocol/v1/session-setup) · [Exterior MCP endpoint decision](../adr/0030-a-web-app-serves-mcp-through-the-relay.md)

For filesystem skills, ACP v1 accepts absolute `additionalDirectories` on supported lifecycle methods only after negotiation. The client must repeat the intended roots on load or resume. The paths refer to the agent's environment. The ACP filesystem calls go the other direction, enabling an agent to ask its client for text files. They provide no client-to-device directory installation. The v2 Agent Skills schema landed behind an unstable feature on November 14. It lets the agent advertise typed skills and the user invoke a known skill by name. The proposal leaves client-supplied skills to MCP or workspace roots. [Additional workspace roots](https://agentclientprotocol.com/protocol/v1/session-setup#additional-workspace-roots) · [ACP filesystem](https://agentclientprotocol.com/protocol/v1/file-system) · [ACP Agent Skills RFD and history](https://agentclientprotocol.com/rfds/agent-skills)

## The separate filesystem option

When the app or device administrator already provisions skill directories, the client can supply the device path to Claude or Codex after negotiation. A browser app with only a bundled `SKILL.md` has no such path. EAP opens a connection with `deviceId` and `agentName`, and the device launches the configured process before returning an attach ticket. The SDK's device launcher receives the agent name and working directory. An app-specific filesystem distribution feature would need a device operation that identifies the authorized app, provisions its selected files, and returns a scoped path before ACP session setup. Keep the ACP data stream opaque. A launch-time setting would need to reach the device earlier, before it spawns the process. [EAP connections](../protocol/exterior-agent-protocol.md#62-connections) · [Device host](../../packages/sdk/src/device/host.ts) · [Gateway launch](../../packages/gateway/src/host.ts) · [ACP carriage decision](../adr/0002-passthrough-acp-frames.md)

An explicit install of a selected, versioned app bundle and an MCP resource cache have different trust semantics. SEP-2640 requires a host's disk cache to stay outside all filesystem skill discovery paths and retain MCP origin. A gateway that silently places fetched MCP resources under `.agents/skills` would defeat this rule. For a distinct filesystem installation, derive paths from validated relative bundle entries, preserve relative references, reject name collisions in the app bundle, and identify the app and content revision when presenting it for installation. Native harnesses resolve local collisions differently. Files and paths must remain available while sessions still depend on them. Avoid shared project or user skill directories for temporary per-app activation. [MCP verification and origin](https://modelcontextprotocol.io/extensions/skills/overview#integrity-and-verification) · [Agent Skills directory format](https://agentskills.io/specification) · [Claude collision rules](https://code.claude.com/docs/en/skills#resolve-skills-that-share-a-name)

For an explicitly requested Node installer, Vercel's published `skills` **1.9.0** has a programmatic `installSkills` interface. Its documented staging example copies into a private `.agents/skills` root with `lockfile: false`, duplicate rejection and symlink rejection. It requires Node 22.20 or later. The Agent Skills project's Python `skills-ref` supplies frontmatter and validation examples and describes its own scope as demonstration. Neither dependency is needed by a browser app that publishes its files with the official MCP SDK. [Published Vercel package](https://registry.npmjs.org/skills/1.9.0) · [Programmatic API at the published commit](https://github.com/vercel-labs/skills/blob/50894c1d98bc45ca1ab127213e59d6525065b5e7/docs/api.md#installing-into-a-plain-directory) · [Agent Skills reference library](https://github.com/agentskills/agentskills/tree/83021e2be457a9b6679148719c1f6074f0ad975e/skills-ref)
